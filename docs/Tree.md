# `/yfxl99` Welcome 像素树实现任务

> 状态：已实现并完成本地验收（2026-08-18）。
>
> 执行本任务时，必须先阅读项目根目录的 `CODEX.md`、`AGENTS.md` 和 `README.md`，并保留现有登录、Session、私密路由、Navbar、Supabase RLS 与 Signed URL 机制。
>
> 验证说明：已在真实 Chrome WebGL2 环境检查 1440×960 桌面和 390×844 手机布局；真实 Supabase 照片数据未在本机提供，活跃度纯函数、服务端聚合路径以及未配置/查询失败回退均已实现。当前 `.env.local` 的公开 `projects` 查询在构建期不可用，因此最终生产构建使用项目已有的“未配置 Supabase”回退模式完成，未修改本地环境变量文件。

## 1. 任务目标

在用户登录后的 `/yfxl99` Welcome 首页中，实现一棵完全由程序生成的像素风格生命树。

它不是一张背景图片，也不依赖预先绘制的树木素材。树干、枝杈、树冠、叶片和落叶都应根据一个可复现的随机种子生成，并使用 WebGL2 实时渲染。视觉语言参考体素和像素沙盒游戏的颗粒感：边缘清晰、色块克制、像素尺寸统一，但不得直接复制《Noita》或其他游戏的素材。

核心体验：

- 树干与枝条会随风产生柔和、连续的摆动。
- 树叶由独立的方形像素粒子组成，部分叶片会脱落、飘动并落出画面。
- 树的茂盛程度由私密照片的最后上传时间决定；上传后恢复茂盛，随后按明确时间曲线逐渐变稀。
- 提供一个可折叠控制面板，让维护者实时调整树、风、落叶和渲染参数；正式页面默认隐藏面板和入口。
- 页面仍然是 `/yfxl99` 的 Welcome 首页，不得影响未登录状态下的密码表单。

## 2. 当前项目上下文

- 技术栈：Next.js 16、React 19、TypeScript、Tailwind CSS 4、Supabase。
- 私密入口：`src/app/yfxl99/page.tsx`。
- 登录后的首页内容：`src/components/private/WelcomeHome.tsx`。
- 照片数据表：`photo_entries`。
- “最后上传时间”以 `photo_entries.created_at` 为准，不使用照片拍摄日期 `photo_date`。
- 照片统计只能在服务端、且通过现有私密 Session 校验后读取；浏览器端只接收渲染所需的聚合结果，不得接收 Service Role Key 或额外的照片隐私数据。

## 3. 页面与构图

### 3.1 布局

- 保留现有 `PrivateNavbar`，树场景占据 Navbar 下方的主要可视区域。
- 桌面端和移动端的树都位于画布水平中心，控制面板覆盖在左侧或移动端紧凑浮层中，但不改变树的投影中心。
- 场景最小高度为 `calc(100svh - Navbar 高度)`，避免移动浏览器地址栏变化导致跳动。
- 画布铺满场景，但不得覆盖导航栏，也不得阻止控制面板的鼠标和触摸操作。
- 不显示 Welcome 标题和说明文案；树下方保留增量时间显示，不能遮挡树根和控制面板。

### 3.2 视觉方向

- 背景使用低饱和的深色或暮色渐变，不能使用纯黑大底造成细节丢失。
- 树干采用 3～5 个相邻的暖灰、棕色或灰紫色阶，避免平滑写实渐变。
- 叶片使用 4～6 个同一色系的离散颜色，默认使用参考像素画取向的雾白色板，并保留春绿、秋金、夜蓝色板。
- 叶片尺寸由算法自动分层：3px 铺树冠底层体块，2px 形成中层轮廓，1px 补边缘、高光和空隙细节；不提供人工尺寸参数。
- 先渲染到低分辨率离屏缓冲区，再以 nearest-neighbor 放大，保证像素边缘清晰；禁止被浏览器双线性插值模糊。
- 树根与地面只做必要的像素暗部，不添加与主题无关的复杂场景、贴图或大面积发光特效。
- 树根上方叠加固定落叶像素，颜色跟随当前叶片色板；落叶先形成贴地的连续薄底层，再在树干附近组成三个相互重叠的小堆，中央略厚、两端渐薄。上层像素必须有底层承托，不能随机悬在空中；它不随照片密度消失，也不参与风场和动态落叶回收。

## 4. 程序化树生成

### 4.1 可复现随机

- 使用可指定的字符串或整数 `seed` 创建确定性伪随机数生成器。
- 相同 seed 和相同结构参数必须生成相同的树形，刷新页面不能无故改变。
- “随机新树”按钮负责生成新 seed；“重置”按钮恢复默认参数和默认 seed。

### 4.2 树的结构

- 使用递归分枝、L-system 或等价的程序化方法生成主干和枝条骨架。
- 树干底部通过一对低矮根颈自然向外展开，再连接 3 根较短辅根；共 5 根主根使用 2～3 段浅弧线贴地收细，不允许从同一点放射或明显向地下扎成爪状。
- 左右主根大致平衡但长度和曲率略有差异；根部只露出隆起的上半部分，末端由固定落叶薄层遮住。左右落叶小堆的中心跟随两根最长主根的落点，使树根、地面和落叶形成一个连续基座。
- 每个枝段至少保存起点、终点、层级、父节点、粗细和相位偏移。
- 分枝角度、长度衰减、曲率和左右不对称程度允许受 seed 影响，但结果必须维持自然、稳定的整体轮廓。
- 枝条粗细应随层级递减，末端不能出现比父枝更粗的情况。
- 树叶候选点从末级枝条附近的树冠体积分布中生成，不能简单填充为一个规则圆形。
- 叶片使用独立方形像素表示，不使用图片纹理；每个候选点根据它在叶团中的径向位置和受光位置，确定为 3px、2px 或 1px 层级。
- 先绘制 3px 底层，再绘制 2px 中层，最后绘制 1px 细节层；叶片密度变化时三层仍均匀分布，不能整层突然消失。
- 树形参考 `fff384aef3b21cd158dd32483f826f0d.jpg` 的宽阔伞形体量：低位枝条尽早横向展开，重叠叶团覆盖更多枝干，让树冠更大气、裸露树干相对更小。
- 使用独立的 seed 派生固定根部落叶位置，避免新增地面细节改变相同 seed 的树干和树冠形态。

### 4.3 树下增量计时

- 起点固定为北京时间 `2020-09-26 00:00:00+08:00`，不使用浏览器本地时区重新解释该日期。
- 显示从起点至当前时刻累计的总天数、小时、分钟和秒，单位依次为 `day`、`h`、`m`、`s`。
- 秒数每秒滚动更新；小时、分钟和天数仅在各自数值变化时滚动。
- 使用当前时间戳重新计算差值，不用每次简单加一，避免后台标签页节流造成累计误差。
- `prefers-reduced-motion` 开启时停止滚动过渡，但时间数值继续准确更新。

### 4.4 风摆动

- 摆动幅度随枝条高度和层级增加：树根基本固定，细枝与树冠响应更明显。
- 风由低频主摆动、较小的高频细节和偶发阵风组成，避免所有枝条同相位机械摇摆。
- 父子枝条的变形必须连续，不能出现枝条断裂或连接点漂移。
- 风参数改变时要平滑过渡，不允许画面瞬间跳变。

## 5. 照片活跃度与叶片稀疏度

### 5.1 服务端统计

在现有照片 Service Layer 中增加一个只返回聚合数据的方法，例如：

```ts
interface PhotoActivityStats {
  daysSinceLastUpload: number | null;
  vitality: number; // 0～1
}
```

要求：

- 调用前继续执行现有私密 Session 校验。
- 只查询最新一条 `created_at` 并计算最后一次上传距今天数，不再查询或传递最近 30 天上传次数。
- 使用服务端当前时间计算结果，避免依赖浏览器时间。
- 客户端只接收上述统计，不需要照片 URL、标题、位置、标签等数据。
- Supabase 未配置或读取失败时，页面仍可渲染；自动叶片密度回退为 0%，并在服务端记录错误，不向用户泄露数据库细节。

### 5.2 密度计算规则

将计算写成独立的纯函数，并限制输出范围：

```text
如果从未上传：
  vitality = 0
如果距最后上传不超过 21 天：
  vitality = 1
如果距最后上传大于 21 天且小于 40 天：
  progress = (daysSinceLastUpload - 21) / (40 - 21)
  vitality = 1 - progress³
如果距最后上传大于或等于 40 天：
  vitality = 0

vitality = clamp(vitality, 0, 1)
```

这样可以保证：

- 上传任意一张照片后，树立即恢复 100% 叶片密度，上传次数不额外叠加。
- 前 21 天保持 100%；第 21～40 天使用 `1 - progress³`，以先慢后快的速度减少。
- 第 40 天起叶片密度为 0%，不设置最低叶片保留量；完整树干和页面界面继续显示。
- 数据变化通过目标值插值到当前值，至少用 1～2 秒完成视觉过渡。

默认映射关系：

```text
目标静态叶片数 = round(候选叶片总数 * vitality)
落叶生成率     = 基础落叶率 * vitality 相关系数
```

手动控制面板只能覆盖当前浏览器中的视觉结果，不得回写或伪造照片统计。

## 6. 落叶粒子

- 从当前仍附着在树冠的叶片中随机选择脱落源点，不能从画布任意位置凭空出现。
- 每片落叶至少包含位置、速度、颜色、尺寸、旋转/翻转相位、寿命和随机风响应系数。
- 运动由重力、空气阻力、水平风场和轻微湍流共同决定。
- 落叶越过地面或寿命结束后回收到固定大小的对象池，不持续创建垃圾对象。
- 可保留少量已经落地的像素，但必须设置上限；达到上限后复用最早的粒子。
- 切换标签页或场景不可见时暂停动画，恢复后不能用巨大的时间步长补算。

## 7. 控制面板

控制面板和入口按钮默认隐藏。在浏览器 Console 输入 `open_tree_control_panel` 并回车后临时打开；点击收起或刷新页面后重新隐藏。该开关状态不持久化，树参数仍按原规则保存。所有输入必须有中文标签、当前数值、合理范围和“恢复默认值”功能。

Console 输入 `refresh_tree` 会在当前浏览器记录刷新时刻、强制恢复自动活跃度，并让叶片密度从 100% 重新开始 40 天周期。刷新时刻保存在 `private-tree-refreshed-at:v1`；新的真实照片上传若更晚则优先。此命令不写入数据库，不创建照片，也不影响从 2020-09-26 开始的页面纪念计时器。

## 8. 推荐技术方案

### 8.1 React 与 Next.js 分层

- `src/app/yfxl99/page.tsx`：保持服务端 Session 判断；登录成功后获取照片活跃度聚合数据。
- `src/components/private/WelcomeHome.tsx`：负责 Welcome 页面布局和把聚合数据传给树场景。
- 新建 Client Component 承载 canvas、控制面板和渲染生命周期；不得把整个 `/yfxl99` 页面改成 Client Component。
- 浏览器 API、WebGL context 和动画循环只能在客户端初始化。
- 开发环境 React Strict Mode 下，挂载、卸载、再次挂载不能产生重复动画循环或重复事件监听。

### 8.2 WebGL2 渲染管线

建议按以下通道组织：

1. 生成确定性的树结构和叶片初始数据。
2. 渲染树干与枝条。
3. 渲染附着叶片实例。
4. 更新并渲染落叶粒子池。
5. 输出到低分辨率 framebuffer。
6. 使用 `NEAREST` 采样放大到屏幕。

优先使用原生 WebGL2、TypeScript 与小型项目内工具函数，不新增大型 3D 引擎。若执行时确需引入依赖，必须先说明它解决的问题、包体积影响和不使用原生方案的原因。

### 8.3 建议文件结构

```text
src/
├─ components/private/
│  ├─ WelcomeHome.tsx
│  └─ tree/
│     ├─ ProceduralTree.tsx       # Client Component 与生命周期
│     ├─ TreeControlPanel.tsx     # 控制面板
│     ├─ config.ts                # 类型、默认值、范围
│     ├─ activity.ts              # 活跃度映射纯函数
│     ├─ generation.ts            # seeded PRNG 与树结构生成
│     ├─ renderer.ts              # WebGL2 初始化及绘制调度
│     ├─ particles.ts             # 落叶对象池和更新逻辑
│     └─ shaders.ts               # shader 源码
└─ services/
   └─ photoService.ts             # 新增私密照片聚合统计
```

具体拆分可以按实现复杂度微调，但不能把所有逻辑堆在单个超大组件中。

## 9. 响应式、性能与稳定性

- 使用 `ResizeObserver` 或等价机制同步画布显示尺寸，并限制 DPR，建议上限为 2。
- 根据设备能力设置叶片上限：移动端建议不超过 3,000，桌面端建议不超过 8,000；实际值以性能测试为准。
- 目标性能：常见桌面设备稳定接近 60 FPS，中端移动设备不低于 30 FPS。
- 避免每帧重新生成树、创建大量数组、对象或 WebGL buffer。
- 页面隐藏、组件卸载时停止 `requestAnimationFrame`，释放 buffer、program、texture 和 framebuffer。
- 监听 `webglcontextlost` / `webglcontextrestored`，上下文恢复后可以重新初始化场景。
- WebGL2 不可用时显示程序生成的静态 Canvas 2D 树或清晰的轻量降级画面，页面不能白屏或阻断导航。
- 数据获取失败、窗口尺寸为 0、参数超出范围等情况必须有安全默认值。

## 10. 可访问性与动效偏好

- Canvas 作为装饰画面时使用 `aria-hidden="true"`，同时提供一段可读文本描述当前树的状态。
- 控制面板所有控件都有可关联的 `label`，焦点样式清晰，Tab 顺序合理。
- 检测并实时监听 `prefers-reduced-motion: reduce`：偏好生效时停止 WebGL RAF、落叶和阵风，只保留一次静态渲染；系统偏好恢复后才按面板中的播放状态继续动画。
- 色板和文字对比度满足 WCAG AA；状态不能只靠颜色表达。
- 移动端触控目标不小于约 44×44 CSS 像素。

### 10.1 动画性能审查结果（2026-08-19）

- `PixelTreeRenderer` 不再在每一帧复制、排序飘落叶，也不再逐帧创建树干与叶片色板数组。
- 可见叶片和飘落叶使用按 2 倍容量增长的复用 `Float32Array`，只在容量不足时扩容；常规帧通过 `bufferSubData` 更新已有 WebGL buffer。
- 3px / 2px / 1px 的绘制层次改为三次线性遍历，保持原有“大像素先画、细节后画”的视觉顺序，同时消除每帧 `sort` 与临时对象造成的 GC 抖动。
- 页面隐藏、暂停、组件卸载和 Reduced Motion 均会停止 RAF；重新显示时重置时间戳，不会因为后台停留产生一次大步长跳动。
- production Chrome 在桌面与 390×844、DPR 2 的移动视口中连续采样 2 秒，均为 120 帧，P95 帧间隔约 17.1ms / 16.9ms，没有超过 25ms 的帧；Reduced Motion 下两次树冠截图哈希一致。

## 11. 安全边界

- 不改变 `/yfxl99` 现有密码校验、Cookie、Session、限流和登出逻辑。
- 不允许客户端直接查询 `photo_entries`，也不允许把 Supabase Service Role Key 放进 `NEXT_PUBLIC_*` 变量。
- 不为私密表新增 anon/authenticated 读取策略。
- 不因为树场景而生成或暴露照片 Signed URL。
- `/yfxl99` 继续保持私密页面的 robots/noindex 策略。

## 12. 验收标准

### 12.1 视觉与交互

- [x] 登录后访问 `/yfxl99` 能看到完整的程序化像素树，默认看不到控制面板或入口按钮。
