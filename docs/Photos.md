# Photos 页面实现说明

## 1. 目标

`/yfxl99/photos` 是私密照片档案。页面沿用 Food 已验证的视觉和交互语言，但保持照片本身为视觉主体，不增加多余标题或装饰。

核心原则：

- 一张照片对应一条 `photo_entries` 记录。
- 页面进入后直接显示照片画廊，不显示 `Photos / Private archive` 等页头文案。
- 小卡片等宽，宽度由页面宽度和响应式列数决定，高度严格保持原图比例。
- 普通点击翻面；按住约 450ms 后在当前画廊中原位展开。
- 展开不是新页面，也不是遮罩式详情 Dialog；其他卡片通过布局动画自然让位。
- 已有卡片展开时选择另一张，先完整收起前一张，再展开后一张。
- 图片、数据库字段和写接口均属于私密数据，只能通过有效 Session 访问。

## 2. 页面布局

页面主体使用与 Food 相同的 `container-shell` 宽度：

- 小于 360px：1 列。
- 手机：2 列。
- 中等屏幕：3 列。
- 宽屏：4 列。

同一断点下所有普通卡片等宽。瀑布流使用 1px 网格高度步进，行间视觉间距放在图片容器之外，避免网格取整改变图片比例。

画面使用暖灰、纸张白、深橄榄灰和低饱和砖色。允许圆角、细边框、克制阴影，不使用渐变、玻璃拟态或大面积发光。

## 3. 普通卡片

### 3.1 正面

- 完整显示原图，不使用 `object-cover` 裁切。
- 图片容器比例来自数据库保存的真实 `width / height`。
- 旧照片没有可靠尺寸时，图片加载完成后使用浏览器 `naturalWidth / naturalHeight` 修正比例。
- 底部显示标题；没有标题时显示“无题”。
- 右上角显示简短日期。

### 3.2 背面

- 标题。
- 中文地区。
- 中国北京时间。
- 标签。
- 文本过长时截断，完整内容放在展开卡片中。

### 3.3 手势

- 普通点击：翻面。
- 鼠标、触控、触控笔统一使用 Pointer Events。
- 按住 450ms 且移动不超过 10px：展开详情。
- 移动超限、抬起、取消或丢失 pointer capture：取消长按。
- 背面提供“展开”按钮，使键盘用户不依赖长按。

## 4. 画廊内展开

- 展开卡片仍然是 `.photo-gallery` 内原来的网格项。
- 桌面约占两列，左侧完整图片，右侧显示资料与操作。
- 手机占满画廊宽度，图片在上、资料在下。
- 展示标题、完整地区、北京时间、描述和全部标签。
- 提供“修改”“删除”“收起”，卡片外侧提供上一组、下一组切换按钮。
- `Escape` 可以收起，焦点返回原卡片。
- 收起时恢复普通卡片原有宽度和高度。
- 目标切换分为两段：先等待旧卡的收起与网格复位，再展开新卡。
- 使用 FLIP 动画推动周围卡片；Reduced Motion 下即时完成布局变化。

## 5. 新增照片

右下角固定圆形 `+` 按钮打开上传 Dialog。一次上传一张照片并建立一条记录。

字段：

- 图片：JPEG、PNG、WebP，最大 10MB。
- 标题：可选，最多 120 字符。
- 描述：可选，最多 2000 字符。
- 拍摄时间：必填，中国北京时间；优先读取 EXIF，没有时使用当前时间。
- 地区：使用与 Food 相同的地区选择器，只显示和提交中文名称。
- 标签：可选，最多 20 个，每个最多 30 字符。

上传流程：

1. 浏览器读取真实尺寸、MIME、字节数和 EXIF 时间。
2. `init` 创建 `draft` 数据库记录和不可预测的 UUID 路径。
3. 浏览器向受保护的同源 PUT 接口上传原始文件。
4. 服务端复验文件头、真实尺寸、MIME 和字节数。
5. `complete` 将记录切为 `ready`，画廊才会显示。
6. 取消或失败时清理草稿与精确文件；超过 24 小时的旧草稿会延迟清理。

## 6. 修改与删除

修改允许更新：

- 标题。
- 描述。
- 拍摄时间。
- 中文地区。
- 标签。

所有已登录账号都可以修改或删除任意照片记录。修改面板允许替换原图并同步生成新的缩略图；新增仍使用页面右下角的新增按钮。删除前必须确认，删除整条数据库记录和对应图片。

删除顺序：

1. 将 `ready` 记录临时切换为 `draft`，立即从画廊隐藏。
2. 按图片实际来源删除本地文件或旧 Supabase Storage object。
3. 删除数据库行。
4. 文件删除失败时尝试把记录恢复为 `ready`。

## 7. 统计

左下角“统计”按钮在画廊上方展开统计面板，至少包含：

- 照片总数。
- 国家数、城市数、标签数。
- 有描述的照片数。
- 第一张照片日期与距今天数。
- 最近一年照片数。
- 地区排行、标签排行。
- 最近十二个月时间线。
- 往年今日。

## 8. 数据结构

保留现有 `photo_entries`，增量添加：

- `occurred_at`、`timezone`。
- 国家、地区、城市代码与中文名称。
- `width`、`height`、`mime_type`、`byte_size`、`captured_at`。
- `status`、`upload_request_id`、`legacy_record`。

旧行原样保留并标记 `legacy_record = true`。旧 `storage_path` 不迁移、不删除，继续通过 Supabase 私密 Signed URL 读取。

## 9. 图片存储

新照片的数据库路径固定为：

```text
photos/{photoId}/{photoId}.{jpg|png|webp}
```

实际根目录由服务端环境变量决定：

```text
PHOTO_STORAGE_ROOT=/data/mypage
```

未配置时依次回退到 `FOOD_STORAGE_ROOT` 和项目内 `.data/private-media`。数据库永远只保存 `photos/...` 相对路径，不保存 Windows 盘符、服务器绝对路径或腾讯云域名。

以后部署腾讯云时，只需把 `PHOTO_STORAGE_ROOT` 指向持久云硬盘挂载目录；若改成 COS，应替换服务层的文件适配器，不修改数据库相对路径和 UI。

## 10. 安全要求

- 页面、图片读取和所有 API 都要求有效私密 Session。
- 写接口要求同源 `Origin`、请求限流和 JSON/文件大小上限。
- 文件名全部使用服务端 UUID，不使用原始文件名。
- 服务端拒绝绝对路径、目录穿越、错误扩展名和非预期 MIME。
- 浏览器提供的尺寸、时间和类型只作声明，发布前由服务端复验图片内容。
- `photo_entries` 不增加 anon/authenticated Policy，仍只允许 service-role 服务端访问。

## 12. 部署顺序

1. 在 Supabase SQL Editor 执行 `202608190001_photo_local_gallery.sql`。
2. 配置 `PHOTO_STORAGE_ROOT`，确保 Next.js 进程可读写且目录位于持久磁盘。
3. 重新启动应用。
4. 登录后打开 `/yfxl99/photos`，上传一张测试照片。
5. 验证翻面、长按展开、修改、删除、统计和移动端布局。

Migration 尚未执行时，页面继续兼容显示旧照片，但会明确提示并禁用新增、修改和删除。

## 分组照片

执行 `supabase/migrations/202609050001_photo_groups_and_images.sql` 后，`photo_entries` 保存一组照片的标题、描述、时间、地点和标签，`photo_images` 保存组内有序图片。旧照片会自动变成只有一张图片的组，不移动本地原图或缩略图。

- 每组 1–12 张，单张最大 10MB，单组最大 60MB。
- 已保存的组可继续添加、替换或删除单张图片，最后一张需通过删除整组记录移除。
- 新增和替换时由服务端直接解析原图像素尺寸，不依赖页面提交的宽高。

## 15. 动画性能审查（2026-08-19）

- Photos 与 Food 现共用 `src/lib/motion.ts` 的 FLIP 和 Dialog 退出实现，避免两套动画参数逐渐分叉。
- 画廊布局动画为 420ms 的快速收尾曲线；中断时从当前可见帧继续，不再取消动画后瞬间跳到终态。旧卡仍完整收起后才展开新卡。
- `will-change` 只在实际布局动画运行时存在，完成、中断或组件卸载后立即清除；卡片翻面不再永久请求合成层。
- 长按期间有轻微压下反馈，正常纵向滚动超过 10px 后取消长按；触摸设备不执行鼠标悬停上浮。
- 统计面板支持平滑打开与收起，新增/修改 Dialog 支持进入、退出和遮罩过渡；系统 Reduced Motion 会将全部非必要动画变为近乎即时。
- production Chrome 以 8 张本地假图在桌面和 390×844、DPR 2 下验证：展开仍位于 `.photo-gallery` 内，650ms 采样的 P95 帧间隔约为 17.0ms / 16.9ms，没有超过 25ms 的帧，运行时错误为 0。测试未访问或修改正式图片与数据库，临时入口已删除。
